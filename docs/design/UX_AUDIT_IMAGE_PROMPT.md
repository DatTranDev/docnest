# docsnest editor concept: generation prompt

Generated for the UX audit dated 10 October 2026 with the built-in imagegen tool. The image is a concept proposal, not implementation evidence. The audit's layout specification is authoritative if the generated lettering or dimensions differ.

Use case: ui-mockup
Asset type: high fidelity product design proposal, desktop and mobile side by side, for a Markdown UX audit.
Primary request: redesign the existing docsnest online document editor for ages 18–25 to make writing immediately accessible and save state clear. Create one polished, precise flat UI concept board, landscape roughly 1800 by 1100. This is a proposed cloud editor, not a screenshot of the current app.
Composition: wide desktop editor on the left occupying 72 percent; a readable narrow 390px mobile layout on the right occupying 25 percent. Small board caption "docsnest / Editor concept". White and cool pale gray workspace, restrained cobalt blue #2458D3 primary actions, ink #202B3A, muted slate #526174, thin gray borders. No cream, gradients, fake charts, AI assistants, comments, invented features, decorative avatars or marketing badges.
Desktop: quiet 56px application bar with the existing document-shaped blue icon and wordmark "docsnest" at far left, a "My files" back link, account initial M at far right. Below, compact document header with editable title "Media studies notes", muted check icon and exact label "Saved to your account", quiet outlined "Save", filled cobalt "Share". Small text menu row "File" "Insert" "Format" "View" with "Version history" aligned right. One toolbar only, normal text style, Arial font, 11 size, bold italic underline, text colour icon, list icon, alignment menu, undo and redo, ellipsis. No more than one toolbar row on desktop.
Main canvas: centered clean white document page on cool gray surround. Realistic essay notes, left aligned comfortable text: title "Media studies notes", smaller "How short-form video shapes attention", a paragraph "Our project explores how short-form video changes the way students discover and remember information.", heading "Questions for our study", three bullets "What makes a video memorable?", "When do we choose to stop scrolling?", "How do creators build trust?". Another heading "Next steps" with short ordinary prose "Compare our interview notes and choose three themes for the presentation." Keep the page with ample open writing space. A small secondary page-side action "Edit together" is allowed only as a quiet menu item under Share, do not show live collaborators or claim active collaboration. Do not show a left sidebar while writing.
Mobile: no device photograph or heavy phone frame. Show same document and same saved state in a compact header with back arrow and overflow. Title truncated gracefully to "Media studies notes". First row with small brand, next compact title/status, next short toolbar with B I U list and "Format". Share is an accessible blue action in the title area. Editable document starts within the upper quarter of the mobile viewport and fills the rest; readable 16px body. Further tools hidden behind Format, not wrapped into many rows. No global marketing navigation or language/theme dropdowns on this editing surface.
Style: crisp realistic UI, restrained border radii 8px on controls and 12px only on floating surfaces, minimal shadow, clear text contrast, consistent outline icons. UI chrome uses a humanist sans similar to Segoe UI, document uses Arial. Both versions depict exactly the same document. All visible copy in English and spelled accurately. Label as "Concept proposal" in the board caption, without pretending this is an implemented screen.
