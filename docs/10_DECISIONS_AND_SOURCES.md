## ADR019: maintainable feature architecture

Accepted 4 October 2026 from the owner's refactor requirements. The implemented architecture keeps Java21/Spring Boot4.1.1, the three backend/databases, JdbcTemplate, outbox/inbox, Redis and immutable local/GCS storage. Next.js16.3.8 App Router with React19.3.0 and Node24.11.1 replaces Vite application hosting; Vite remains a Vitest dependency. Thin routes delegate to feature modules. Client-only dynamic boundaries protect CodeMirror, workers and IndexedDB, and editor-core remains framework independent.

Backend business features own API mapping, command/query handlers and read models, ports, plain Java domain policies, and infrastructure implementations. Logical CQRS calls handlers directly and retains the existing database ownership. Extracting orchestration preserves row locks, optimistic head revisions, ACL checks, idempotency, short SQL transactions and atomic outbox writes. Cross-feature interaction uses explicit application interfaces. Common is technical only: codec, storage, messaging and observability. Heavy codec/storage dependencies are optional for consumers; benchmarks compile in test scope and never ship in service jars.

Processing's additive V3 migration stores nullable `jobs.trace_id`. Existing API/event fields stay unchanged. Validated event scopes preserve HTTP→outbox→consumer correlation, and durable job trace storage supports completion after restart. Existing rows may generate a new trace. Structured logs use fixed actions and bounded scalar identifiers; invalid payloads produce only a fingerprint and broker offsets. Private metrics include request/save/validation, durable queue age, DLQ/lease/job/Redis/snapshot observations and native Kafka/JVM meters. Applied V1/V2 migrations remain immutable.

Production Next.js runs behind a Node gateway on port8080, with its child bound to loopback port3000. The gateway enforces streaming size/time limits, origin/header/cookie behavior, private API cache controls and internal-route blocking. Only explicit proxy CIDRs can supply forwarded client addresses. Cloud manifests and migration jobs remain preparation artifacts, and no provisioning is authorized by this ADR.

Pinned quality tools are Spotless3.10.3/Google Java Format1.36.1, ArchUnit1.5.1, Prettier3.9.9, ESLint9.39.5 with eslint-config-next16.3.8, TypeScript5.9.3 and typescript-eslint8.71.0. GJF1.36.1 is the Java21-compatible pin. Next's directory resolver uses the scoped `@ted/lint-glob`1.0.0 adapter with tinyglobby0.2.17, preserving the actual globSync contract and bounded deep-pattern behavior rather than retaining vulnerable braces parsing. Its resolver tests are required. Automated checks reject wildcard Java imports, forbidden backend dependencies, private cross-feature imports and frontend cycles; broad suppressions are not accepted.

Consequences: the web image now contains a production Node process, so resource/OS vulnerability measurements must be repeated; old Nginx scan results do not prove the new image is clean. Formatting, architecture, builds, real-service E2E/restart/backup and representative large benchmarks must be executed after the migration. Previous memory/scroll target misses remain visible; no final pass is inferred from source organization. Current status and gate outcomes belong in docs/PROJECT_STATUS.md. Remote CI and Google Cloud gates remain NOT_RUN/PENDING/DEPLOY_PENDING until executed in their environments.

### Gateway read resilience

Final real-service validation observed intermittent502responses before native download headers. A separate100-request10MiB reopen probe passed with exact hashes; it did not prove the failure's cause. Retain the failed execution and sanitized upstream diagnostics. Following [Node's reused-socket guidance](https://nodejs.org/docs/latest-v24.x/api/http.html#requestreusedsocket), the gateway retries an empty GET/HEAD once only for `ECONNRESET` on a reused upstream socket, before any response headers. The retry uses a fresh socket and the original shared deadline. Writes, reads with bodies, fresh-socket failures and started responses are not replayed. Actual HTTP fault tests cover recovery, non-replay and bounded retry; final full-service tests remain required.

## ADR020: Node runtime OS gate repair

Accepted 5 October 2026 after executing the refactor image OS gate. The exact Node/Bookworm web image had52 High and4 Critical OS package findings despite its APT upgrade layer. The failed image and package counts are recorded here; detailed scan JSON is generated locally and uploaded by CI. It does not become a pass when the replacement is built.

Use official `node:24.11.1-alpine3.23@sha256:682368d8253e0c3364b803956085c456a612d738bd635926d73fa24db3ce53d7` for both build and runtime. Docker Hub's actual multi-platform index and Linux/amd64 manifest were resolved through Docker Buildx and recorded in `testing/reports/node-alpine-registry-inspect.log`. Keep the Node version, Next/React dependencies, gateway behavior, UID1000, loopback Next port3000, public8080, health probes and512MiB runtime limit. Apply APK security updates and gcompat before switching to the node user. Rebuild and rescan the resulting immutable image whenever security package repositories change.

The [official Docker Node documentation](https://github.com/nodejs/docker-node/blob/main/README.md#nodealpine) identifies Alpine's musl libc and gcompat compatibility support; it also identifies musl/amd64 as an experimental Node build tier. The builder therefore uses the same Alpine environment and installs packages there rather than copying glibc-built native modules. Next's [SWC troubleshooting](https://nextjs.org/docs/messages/failed-loading-swc) and [standalone output](https://nextjs.org/docs/app/api-reference/config/next-config-js/output) inform packaging. Linux/amd64 is the local and e2-standard-2 deployment target; other CPU architectures require their own build and runtime checks.

Executed Linux/amd64 evidence: the production Next16.3.8 webpack build passed in the Alpine builder; nine gateway contracts passed inside Node24.11.1/musl; the latest source SHA256 matches the built gateway; replacement web readiness passed; and its exact final image had zero OS findings across21 packages. The generated `testing/reports/node-runtime-compatibility.json` connects image ID, registry proof, source hash and build/runtime/scan logs; CI uploads it as an artifact. The failed Debian scan outcome is recorded in this decision; its raw scan output is a generated CI artifact. Full real-service smoke/E2E after replacement is recorded separately in the application reports, and other CPU architectures remain NOT_RUN. The existing High/Critical and incomplete-scan publication rejection remains enforced. Java image lower-severity findings and application dependency scans keep their separate scope. No cloud resources or billing are created by this change.

## Collaboration after the MVP

Create the next unused ADR when this work begins (currently ADR022). A server revision/CRDT clock differs from the snapshot head revision. CRDT formatting requires range anchors and grapheme semantics. Local undo reverses the caller's intent, not the whole remote state. Collaboration Service uses WebSocket, Redis TTL presence, a durable operation log and Document snapshot integration. Do not reuse the current HistoryManager to undo remote changes without rebasing. Load, quotas, budget and WebSocket authentication need separate benchmarks.

## ADR021: repository folders by responsibility

Accepted 7 October 2026 for a compact repository root. Java services and SQL live under `backend`; Next.js and editor-core under `frontend`; infrastructure under `infra`; cross-application tests, benchmark runners, fixtures and generated reports under `testing`; operational tools under `tooling`; specifications, contracts and maintenance guides under `docs`. Keep unit tests beside their owning implementation and root configuration where Maven/npm require it. These moves change no API, event, database, native format or service ownership. Classpath resources retain their existing names independently of source-tree paths. Historical evidence remains immutable and must not be relabeled as validation of relocated sources. The sole project checkpoint is `docs/PROJECT_STATUS.md`.
